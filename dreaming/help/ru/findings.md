## Зачем этот раздел

Долг — список: плоский перечень находок сканера технического долга. Каждая
находка — отдельный markdown-файл с фронтматтером: что не так, в каком
модуле, насколько срочно, насколько сложно чинить и может ли агент починить
это сам.

Это рабочий экран: отсюда находку закрывают, заводят по ней задачу в GitHub
или отправляют её оркестратору на исполнение.

## Откуда берутся данные

Из каталога `tech_debt_dir` (задаётся в настройках проекта). Файлы туда
пишет сканер — команда `tech-debt-scan`, которая запускается кнопкой на этой
же странице или по расписанию. Сверху видно, когда скан отработал в
последний раз и не идёт ли он прямо сейчас.

Приложение читает и правит эти файлы напрямую. Все изменения статуса — это
переписанная строка во фронтматтере, а не запись в базу. Значит, находки
переживают переустановку приложения и попадают в git вместе с проектом.

## Что на экране

Таблица с колонками:

| Колонка | Что означает |
|---|---|
| **id** | Идентификатор находки, он же имя файла. |
| **title** | Краткая формулировка проблемы. |
| **status** | `open`, `in-progress`, `closed`, `dropped`, `blocked` и любое другое значение, какое поставит агент. |
| **priority** | Срочность. Сортируется по смыслу, а не по алфавиту. |
| **module** | Часть проекта, к которой относится находка. |
| **complexity** | Оценка трудоёмкости починки. |
| **autonomy** | Может ли агент починить это без человека. |
| **confidence** | Насколько сканер уверен, что это вообще проблема. |
| **created** | Когда находка появилась. |
| **refs** | Ссылки: заведённый GitHub-issue и подобное. |

Под заголовками — строка фильтров по каждой колонке, плюс фильтры по статусу
и модулю в адресной строке. Отбор идёт по загруженному списку в браузере.

Слева в каждой строке — чекбокс: находки можно выделить и закрыть или
удалить пачкой.

## Что можно сделать

- **Запустить скан** — перечитать проект и обновить список находок.
- **Открыть находку** — полный текст с описанием и предлагаемым решением.
- **Сменить статус** — поле принимает произвольное значение; осмысленность
  выбора на вашей совести, приложение ничего не валидирует.
- **Закрыть** — частый случай смены статуса, вынесен отдельной кнопкой.
- **Удалить** — убрать файл находки насовсем.
- **Завести GitHub-issue** — создаёт задачу с заголовком `[<проект>]
  <название>`, телом из находки и ссылкой обратно в приложение. Метки:
  `tech-debt` и приоритет. Ссылка на созданный issue сохраняется во
  фронтматтер, так что дважды одну находку не заведёшь по недосмотру.
  Репозиторий берётся из настройки `github_repo` либо определяется по
  рабочему каталогу.
- **Отправить в оркестрацию** — запустить оркестратора с этой находкой как
  задачей. Дальше следить за ним в разделе «Оркестрация».
- **Массовые действия** — закрыть или удалить всё отмеченное.

## Связь с другими разделами

- **Долг — обзор** — те же данные, но агрегированно: по модулям и
  приоритетам, без построчного разбора.
- **Оркестрация** — куда уезжает находка, отправленная в работу.
- **Проверка** — сюда попадают результаты ревью, это отдельный поток находок.
- **Sidecar-находки** — ещё один независимый источник находок.

## Если что-то не так

- **Пусто, и написано, что каталог не задан** — задайте `tech_debt_dir` в
  настройках проекта или нажмите настройку одной кнопкой на дашборде.
- **Каталог задан, но список пуст** — скан ни разу не запускался. Кнопка
  вверху страницы.
- **Ошибка разбора вместо списка** — один из файлов находок имеет битый
  фронтматтер. Текст ошибки показывается на странице.
- **GitHub-issue не создаётся** — либо не настроен `github_repo`, либо в
  рабочем каталоге нет доступного `gh`-клиента с авторизацией.
